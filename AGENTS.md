# PROJECT_LOG.md — keep it current

`PROJECT_LOG.md` is the project's cross-session decision log (read it first when
picking up the project). Update it at meaningful moments, not per commit:

- A data source goes live, is verified, or is deferred/blocked
- A cost or API behavior fact is verified (e.g. Apify pricing, scraping quirks)
- A design, ranking, or architecture decision is made
- A new dev-flow gotcha is discovered (e.g. WSL2/QR/server issues)
- Next steps change or complete

Do NOT log routine code changes, test runs, or the current event count — §2
"Nuvarande läge" is the only place that tracks overall state; refresh it when
it becomes stale. Never restate unchanged sections; edit only what changed.
